# 实时队列与丢帧（Frame Drop）

> 环境：实时帧队列（通用）
> 验证：未复核（2026-09-19 仅做仓库整理，未在本机重跑步骤）

## 什么是丢帧

数据已经产生，但被缓存策略丢弃或覆盖，消费者从未处理到该帧。

## 两种缓存策略

### 主动丢帧（保留最新）

```text
┌─────队列─────┐
[frame8][frame9][frame10] ← 新帧到达 → 丢掉最旧 frame8
        ↑ 始终保留最新几帧
不阻塞 | 有丢帧 | 实时性强
```

适合：视觉预览、遥操、控制闭环——宁可丢旧帧，也要最新状态。

### 阻塞 / 不丢帧

```text
┌─────队列─────┐
[frame1][frame2][frame3]  ← 已满，生产者阻塞
↑ 不能 put 新帧，等待消费者 get()
阻塞 | 不丢帧 | 实时性差，可能堆积延迟
```

适合：必须逐帧处理的离线分析、录制完整性优先的场景。

## 选型要点

| 需求 | 倾向 |
| --- | --- |
| 低延迟、最新状态 | 有界队列 + 主动丢旧帧 |
| 不丢任何样本 | 阻塞队列或落盘，接受延迟 |
| 生产远快于消费 | 必须明确丢弃策略，否则内存涨或延迟爆炸 |

实现时把队列长度、丢弃策略和监控（丢帧计数、队列深度）写清楚，避免“看起来卡”却不知道是阻塞还是在丢帧。
